# rg52remote — экран и управление RG52 Mini (dArkOS) с ПК

Живая картинка с устройства, скриншоты, нажатия кнопок геймпада, клавиатура и
мышь — по сети, без сборки чего-либо на устройстве. Аналог `adb screencap` +
`adb shell input` для dArkOS.

## Что нужно

* На устройстве: dArkOS (RG52 Mini), включённые **Remote Services** (ssh).
  Всё остальное в образе уже есть: `ffmpeg` с `kmsgrab` и `h264_rkmpp`,
  `python3-evdev`, `/dev/uinput`.
* На ПК (Windows или Linux): Python 3 (только стандартная библиотека, tkinter
  для окна), `ffmpeg` и OpenSSH (`ssh`, `scp`) в PATH. Для первичной установки
  ключа нужен `sshpass`: на Windows — внутри WSL, на Linux — обычный
  (`sudo apt install sshpass`).

Адрес устройства: `--host <ip>` или переменная `RG52_HOST`, по умолчанию
`192.168.1.104`.

## Первый запуск

    python rg52remote.py setup     # один раз на карту: кладёт ssh-ключ (id_rg52) на устройство
    python rg52remote.py start     # после каждой перезагрузки устройства: заливает и запускает демон

`setup` повторить после перепрошивки карты; `start` — после перезагрузки
устройства (демон живёт в `/tmp`).

## Команды

    python rg52remote.py view                 # окно: живая картинка + управление
    python rg52remote.py shot [файл.png]      # скриншот (по умолчанию run\shot.png), печатает путь
    python rg52remote.py btn a [мс]           # кнопка геймпада
    python rg52remote.py hold l1 / release l1 # удержать / отпустить
    python rg52remote.py key enter            # клавиша клавиатуры (KEY_ENTER, f1, a, ...)
    python rg52remote.py type "hello"         # набрать текст
    python rg52remote.py mouse 10 -5 | click [left|right|middle] | wheel 1
    python rg52remote.py status | stop
    python rg52remote.py send <команда>       # любая команда демона

Кнопки: `a b x y l1 r1 l2 r2 select start mode fn l3 r3 up down left right`
(по физическим надписям на корпусе: A справа, B снизу).

## Окно `view`

| ПК | устройство |
|---|---|
| стрелки | крестовина |
| X / Z / S / A | A / B / X / Y |
| Q / W | L1 / R1 |
| 1 / 2 | L2 / R2 |
| Enter / Backspace | Start / Select |
| Tab / F | Mode / Fn |
| E / R | L3 / R3 |
| F12 | режим клавиатуры: клавиши уходят на устройство как клавиатура |
| F5 | скриншот в `run\shot-<время>.png` |
| перетаскивание левой кнопкой | движение указателя мыши |
| двойной щелчок / правый щелчок / колесо | клик левой / правой / прокрутка |

Размер: `--zoom 0.5` — начальный размер как доля от 1280×720 (по умолчанию
0.75, то есть 960×540), или `--scale 800` — ширина в пикселях. Окно можно
растягивать мышью: через полсекунды после изменения картинка вписывается в
новый размер с сохранением 16:9 (поток при этом переподключается, на секунду
пропадает). Масштабирует ffmpeg на ПК — нагрузка на устройство та же.
Прочее: `--fps 15 --kbps 2500`.

## Как устроено

* **Картинка** — `ffmpeg -f kmsgrab` на устройстве: снимается плоскость,
  которая сейчас выводится на панель, кто бы её ни рисовал (EmulationStation,
  эмулятор, порт, консоль). Поток кодирует аппаратный энкодер RK3562
  (`h264_rkmpp`) прямо из DRM-буфера: около 4 % одного ядра при 15 к/с.
  Скриншот — тот же захват одним кадром в сыром виде, PNG делает ffmpeg на ПК.
  Панель портретная (720×1280), кадр поворачивается в альбомный.
* **Кнопки** пишутся прямо в настоящий джойстик
  (`/dev/input/by-path/platform-play_joystick-event-joystick`): для программ
  это неотличимо от нажатия, настройки не нужны.
* **Клавиатура и мышь** — отдельное виртуальное устройство uinput, создаётся
  при первой команде.
* Демон `device/rg52remoted.py` работает от root, слушает TCP 5555 (команды)
  и 5556 (поток). **Без пароля** — только для своей сети.

Ограничения: аппаратные оверлейные плоскости (если что-то выводит видео на
отдельный слой) в захват не попадают; громкость и прочие горячие клавиши
срабатывают так же, как при настоящих нажатиях.
